# Watch delivery reliability: tombstones and lossless snapshots

The watch-as-state-source model of ADR 0001 only holds if deletes actually remove state and the final snapshot of an event burst can never be dropped. Informer delete callbacks therefore unwrap `cache.DeletedFinalStateUnknown` tombstones for Pods and Nodes before the type assertion (client-go delivers a tombstone when an object vanishes between a broken watch and the relist that would have reported the delete), and `sendSnapshot` delivers losslessly: it blocks until the model reads the snapshot or the watch context is canceled, replacing the previous drop-on-full send into the buffered channel. Watcher event handlers mutate state synchronously and then signal a coalescing sender, which flushes the latest snapshot after a 50 ms trailing window, so event bursts (notably the initial informer List) collapse to one render per window while the final state remains guaranteed.

Backpressure is absorbed by the sender goroutine, not the handlers: handlers only signal a buffered channel and never block, while the sender blocks until the model reads or the watch context is canceled, and client-go relist self-heals any resulting event backlog. The quit and context-reselection paths already cancel the watch context, so a blocked sender always drains.
